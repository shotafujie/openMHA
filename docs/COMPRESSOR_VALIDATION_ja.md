# 校正付きコンプレッサの数値検証

2026-09-14，macOSの既存ローカルビルドで検証しました．MATLAB，音声デバイス，JACKサーバーは使用していません．C++ホストから上流のプラグインをロードしています．DSPアルゴリズム本体を書き直したものではありません．

## 実装と信号の単位

[process_file.cpp](../examples/cpp-embedding/process_file.cpp) はlibsndfileでWAVを読み，128フレームずつ `mhachain` へ渡し，結果を32ビット浮動小数点WAVに保存します．今回追加した [設定](../examples/cpp-embedding/compressor-chain.cfg) の処理順は次のとおりです．

```text
WAV振幅 → transducersの入力校正 → dc_simple → 出力校正 → WAV振幅
                    Paで処理する区間 ─────────┘
```

入力校正の式は `p = x × 20e-6 × 10^(P_in/20)` です．`x` はWAV振幅，`p` はPa，`P_in` は振幅1に対応させるピーク音圧レベルです．出力は `y = p_out / (20e-6 × 10^(P_out/20))` です．この変換の実装は [transducers.cpp](../mha/plugins/transducers/transducers.cpp) にあります．

テストでは入力ピークレベルを左右 `[100 110]`，出力を `[100 105]` としました．したがってコンプレッサだけをバイパスした場合，正規化振幅は左が不変，右は+5 dBになります．入出力の校正値が異なると，バイパスでもWAVの振幅が変わります．これも検証しています．

これらは仮想的な校正値です．実機の校正には既知の音圧と測定機器を用いた別の作業が必要です．この検証から，実際の音圧や装用時の適切な設定は判断できません．

## 圧縮曲線

`dc_simple` は各チャンネルに独立した圧縮を適用します．今回のステレオ例では各耳を1帯域として処理し，周波数帯域分割はしていません．`g50=0`，`g80=-15` により，50〜80 dBの入力増加30 dBに対して出力は15 dB増えます．この領域は2:1圧縮です．下側の拡張閾値は30 dB，上側のリミッター開始入力レベルは90 dB，最大利得は10 dBとしました．

| 入力レベル（dB SPL） | 期待する出力レベル（dB SPL） |
| --- | --- |
| 10 | 0 |
| 20 | 20 |
| 30 | 40 |
| 40 | 45 |
| 50 | 50 |
| 65 | 57.5 |
| 80 | 65 |
| 90 | 70 |
| 95 | 70 |

この表は時間平滑化を無効にした静的特性です．通常の設定はアタック5 ms，ディケイ50 msです．静的テスト時だけ両方を0に上書きします．波形領域の `dc_simple` はサンプルの絶対値からレベルを求め，平滑化する実装です．テスト信号には絶対値が一定で符号が交互に変わる信号を用い，正弦波のRMSレベルと瞬時レベルを混同しないようにしています．音質評価用の信号ではありません．

## 結果

[verify_compressor.cpp](../examples/cpp-embedding/verify_compressor.cpp) に以下の検査を追加しました．

- 9つの静的入力点と左右の校正換算：最大誤差 `1.01298e-06 dB`（許容0.001 dB）．
- 正負の極性維持，無音入力に対するゼロ出力．
- 動作中に最大利得を3 dBへ変更すると，入力30 dBに対して出力33 dB．
- コンプレッサのみのバイパス時に，左右の校正差が期待どおり残ること．
- 48 kHzの3秒信号を40 → 80 → 40 dBと変化させ，アタックによる利得低下，ディケイによる利得回復，定常値への収束を確認．切り替え点はブロック境界から外しています．
- 同じ信号を64フレームと128フレームで処理した場合の最大絶対差は0．

追加を含むCTestは10件すべて成功しました．時間応答の検証は単調性・収束・ブロックサイズ非依存性であり，5 ms／50 msという時定数を独立に推定して一致させる検査ではありません．物理校正，実機の遅延，聴感，臨床的な有効性，マルチバンド処理は未検証です．
