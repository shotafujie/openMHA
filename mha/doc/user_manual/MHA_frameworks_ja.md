# openMHA フレームワーク

> この文書は [MHA_frameworks.tex](MHA_frameworks.tex) の日本語訳です。

## openMHA フレームワーク（mha コマンド）

openMHA フレームワーク（Linux と macOS では `mha`、Windows では `mha.exe`）は、設定のための制御インターフェースを提供し、openMHA IO モジュールを介してオーディオ抽象化レイヤーに接続します。

テキストベースのユーザーインターフェースは TCP ネットワークソケットを通じて利用できます。また、コマンドラインオプション `--interactive` で起動した場合、openMHA コマンドラインアプリケーションの標準入出力を通じても使用できます。

外部ネットワーククライアント、例えば telnet、netcat、putty、または Octave/Matlab の制御インターフェース関数 `mhactl`（[設定言語の章](MHA_scriptlang_ja.md)参照）を使用してこのインターフェースにアクセスできます。

オーディオ抽象化レイヤーには複数の IO モジュールが利用可能で、プラットフォーム依存性をカプセル化しています（[オーディオ抽象化レイヤー](#オーディオ抽象化レイヤー)参照）。

openMHA フレームワークとすべてのプラグインは、openMHA 設定言語で設定できます（[設定言語](MHA_scriptlang_ja.md)参照）。

## mha の起動

openMHA フレームワークをコマンドライン引数なしで起動すると、TCP ポート 33337、ループバックネットワークインターフェースでネットワークサービスを開始し、ローカルホストからの接続を受け付けて設定言語コマンドを待ちます。

サーバーの動作は以下のコマンドラインオプションで制御できます:

| オプション | 説明 |
|---|---|
| `--quiet` \| `-q` | 出力を抑制し、挨拶テキストやエラーメッセージを表示しません。 |
| `--port=portno` \| `-s portno` | openMHA がバインドするポート番号を設定します（デフォルト: 33337）。ポート番号が 0 の場合、OS が空きポートを選択します。 |
| `--announce=port` \| `-a port` | 指定された場合、openMHA は自身の TCP サーバーソケットを確立した後に localhost のこの TCP ポートに接続し、プロセス ID と使用中の TCP サーバーポートを通知して接続を閉じます。 |
| `--interactive` | 標準入力での MHA コマンドの解釈を有効にします。応答は標準出力に表示されます。標準入力の入力ストリームが閉じられると openMHA は終了します。 |
| `--interface=if` \| `-i if` | openMHA がバインドするネットワークインターフェースを設定します（デフォルト: 127.0.0.1）。 |
| `--daemon` \| `-d` | openMHA をデーモンモードで起動します。MHA サーバーが閉じられた後（`cmd=quit` コマンドで）、openMHA は新しい接続を待ちます。デーモンモードではデーモンプロセスを kill するか、コンソールで `Ctrl-C` を押すことで停止できます。 |
| `--ok-ack=str` \| `-o str` | 受理された MHA コマンド行の確認応答文字列を設定します（デフォルト: `(MHA:success)`）。 |
| `--fail-ack=str` \| `-f str` | 拒否された MHA コマンド行の確認応答文字列を設定します（デフォルト: `(MHA:failure)`）。 |
| `--log=logfile` | ログファイルを設定します（デフォルト: /dev/null）。 |
| `--help` \| `-h` | コマンドライン引数の概要を表示します。 |
| `--lockstr=str` \| `-l str` | 'portno' という名前のファイルを作成し、テキスト 'str' を書き込みます。ファイルは MHA セッション終了後に削除されます。 |
| `--license` | ライセンス契約を表示します。 |

オプションとして認識されない追加のコマンドライン引数は、openMHA 設定言語コマンドとして解釈され、割り当て後、他の入力を受け付ける前に openMHA フレームワークに送信されます。

デーモンモードでは、これらの設定言語コマンドは各セッションの開始時に解釈されます。

`mha --daemon ?read:defaults.cfg` は各セッションで *defaults.cfg* という名前の設定ファイルを読み込みます。

openMHA フレームワークはシステムライブラリパス、または環境変数 `MHA_LIBRARY_PATH` で指定されたディレクトリで openMHA プラグインを検索します。複数のパスはセミコロンで区切ることができます。

**警告**

openMHA フレームワークは、設定されたネットワークインターフェースに到達可能な任意のホストからの接続を受け付けます。送信者認証とトランスポート暗号化は実装されていません。そのため、物理的に分離されたネットワークまたはファイアウォールの背後でのみ openMHA フレームワークを使用することを強く推奨します。患者データの送信の悪用やその他の干渉が発生した場合、一切の責任を負いません。

Octave/Matlab ツール `mhactl` との通信が必要な場合は、確認応答文字列を変更しないでください。

## openMHA フレームワークの設定変数

以下のリストでは openMHA フレームワークの設定変数について説明します。これらの変数はパーサーインターフェース（コンソール入力、TCP など）を通じてアクセスできます。

これらの設定を含む設定ファイルは、設定インターフェースに `?read:filename.cfg` コマンドを送信することで読み込めます。詳細は[設定言語](MHA_scriptlang_ja.md)を参照してください。

変数 `fragsize` と `srate` は、`iolib` に値を割り当ててサウンド I/O ライブラリをロードする前に設定する必要があり、サウンド I/O ライブラリをロードした後は変更できません。これは、一部のサウンド API が初期化時にブロックサイズとサンプリングレートの情報を必要とし、その後変更できないためです。

同じ理由で、初期割り当て後に別の値を iolib に割り当ててサウンド I/O ライブラリを変更することもできません。

歴史的な理由から、変数 mhalib も初期割り当て後は変更できませんが、将来のリリースで緩和される可能性があります。

openMHA が prepared 状態にある場合、入力チャンネル数 `nchannels_in` は変更できません。

openMHA 変数が変更できない場合、それは「ロック」されており、書き込みを試みるとエラーが発生します。

| 変数 | 説明 |
|---|---|
| `nchannels_in` | 入力オーディオチャンネル数。 |
| `fragsize` | オーディオチャンネルあたりのフラグメントサイズ（サンプル数）。`MHAIOJack` を使用する場合、JACK のフラグメントサイズと一致する必要があります。 |
| `srate` | サンプリングレート（Hz）。JACK は `jackd` の起動時に指定された固定サンプリングレートのみ許可します。 |
| `mhalib` | MHA 処理ライブラリ名（例: `transducers`、`mhachain`、`db`）。 |
| `iolib` | IO プラグインライブラリ名（例: `MHAIOJack` または `MHAIOFile`）。[オーディオ抽象化レイヤー](#オーディオ抽象化レイヤー)参照。 |
| `cmd` | openMHA フレームワークの動作状態を制御します。有効な状態（nop、prepare、start、stop、release、quit）は[フレームワークの状態](#openmha-フレームワークの状態)で説明しています。 |
| `mha` | このサブパーサーには処理ライブラリの設定が含まれます。 |
| `io` | このサブパーサーには IO ライブラリの設定が含まれます。 |
| `sleep` | この特殊コマンドは、openMHA がオーディオ処理を続行しながら通常のコマンド実行を待機します。待機する秒数は右辺で指定します（例: `sleep = 5` は5秒待機）。 |

## openMHA フレームワークの状態

openMHA フレームワークの状態は `cmd` 変数を設定することで制御され、状態遷移がトリガーされます。

openMHA フレームワークの現在の状態は、変数 `state` の値を読み取ることで照会できます（例: コマンド `state?`）。

openMHA のすべてのモジュール（フレームワークとプラグイン）を設定した後、`cmd=prepare` を設定することで設定を準備して信号処理の準備を整えることができます。これにより設定の検証も行われます。いずれかのプラグインが現在の設定でオーディオを処理できないと判断した場合、`cmd=prepare` コマンドはエラー結果で拒否されます。

`cmd=start` を設定すると IO プラグインに信号処理の開始を指示し、`cmd=stop` を設定すると IO プラグインに処理の停止を指示します。`cmd=release` を実行すると IO プラグインがアンロック状態になります。`cmd=quit` でセッションを閉じることができます。

![openMHA フレームワークの状態](../images/MHA-fw-states.pdf)
*図: openMHA フレームワークの状態*

変数 `cmd` は状態遷移をトリガーするためのもので、本質的にライトオンリーです。読み取ると常に値 `nop`（"no operation" の略）を返します。これは恒等状態遷移であり、`cmd=nop` を設定しても状態変更は発生しません。

## オーディオ抽象化レイヤー

オーディオ抽象化レイヤーは、JACK（[JACK の使用](#mhaiojack-と-mhaiojackdb-オーディオ-io-モジュール)参照）やオーディオファイルなどのオーディオバックボーンと openMHA フレームワークを接続します。

サウンド入出力に接続するために異なるモジュールが利用可能です:

- **MHAIOJack** — JACK オーディオサーバーを使用した低遅延リアルタイム処理（Linux 向け）
- **MHAIOFile** — ファイル間処理
- **MHAIOJackdb** — MHAIOJack と同様に動作しますが、JACK サーバーのバッファサイズを MHA のバッファサイズの倍数にすることができます（"db" はダブルバッファの略）
- **MHAIOPortaudio** — Portaudio ライブラリを使用して、異なるプラットフォーム固有のオーディオ API に接続します
- **MHAIOalsa** — JACK オーディオサーバーの実行が CPU を多く消費するモバイルハードウェアでの使用シナリオのために、Linux ALSA サウンド API を直接使用します
- **MHAIOTCP** / **MHAIOParser** — ネットワーク接続を介してオーディオを送受信します（一方はバイナリデータとして、他方はテキストとして）。主にテスト目的で使用されます

### MHAIOJack と MHAIOJackdb オーディオ IO モジュール

`MHAIOJack` モジュールは JACK オーディオサーバーとの通信を提供します。

openMHA フレームワークが処理の準備をすると、このモジュールは実行中の JACK サーバーに接続し、パラメータを検証します。MHA の入出力ポートは、openMHA 設定（下記参照）または外部ツールを通じて、任意の他の JACK ポートに接続できます。MHAIOJack は現在、固定のサンプリングレートとフラグメントサイズのみをサポートしています。処理中に JACK のフラグメントサイズを変更すると、MHA 処理スレッドが停止します。JACK が提供しないサンプリングレートが必要な場合は、`downsample` と `upsample` プラグイン、または `resampling` プラグインを使用して openMHA 内部でサンプリングレートを変更できます。

`MHAIOJackdb` モジュールは、実際の JACK フラグメントサイズの整数分の MHA フラグメントサイズを設定できます。例えば、JACK がフラグメントサイズ 1024 サンプルで動作しているが、MHA は 64 サンプルで設定される場合です。その他のフラグメントサイズはダブルバッファリングプラグイン `db` で実現できます。

**MHAIOJack モジュールの変数:**

| 変数 | 説明 |
|---|---|
| `name` | JACK クライアントの名前。複数の MHA インスタンスを同時に実行する場合にのみ変更が必要です。 |
| `con_in` | MHA 入力ポートの接続リスト。各ポートに1つのエントリを持ちます。例: `con_in = [alsa_pcm:capture_1 alsa_pcm:capture_2]`。変数にアクセスするたびにポートが再接続されます。コロンをポート名として使用するとポートを切断できます。1つの MHA ポートへの複数接続を行うには、`qjackctl` や `jack_connect` などの外部接続ツールを使用してください。 |
| `con_out` | MHA 出力ポートの接続リスト。各ポートに1つのエントリを持ちます。例: `con_out = [alsa_pcm:playback_1 alsa_pcm:playback_2]`。 |
| `names_in` | MHA 入力ポートのラベル（自動生成ラベルの場合は空）。 |
| `names_out` | MHA 出力ポートのラベル（自動生成ラベルの場合は空）。 |

`ports` ノードには、JACK の利用可能なハードウェアおよびソフトウェアポートを含むモニター変数があります。

### MHAIOFile オーディオ IO モジュール

`MHAIOFile` モジュールは openMHA でのファイル間処理を提供します。入力ファイル名と出力ファイル名を設定できます。openMHA フレームワークが開始されると（`cmd=start`）、入力ファイル全体が処理され、処理されたデータが出力ファイルに書き込まれます。start コマンドは処理が完了するまで待機します。ファイルは openMHA フレームワークの準備時に開かれ、リリース時に閉じられます。出力ファイルのファイル形式とデータ形式は入力ファイルから継承されます。例えば、入力ファイルが 32 ビット WAVE ファイルの場合、出力ファイルも同様になります。このプラグインは一般的に使用されるほとんどのファイル形式をサポートしています。

**注意:** 整数形式の WAVE ファイルに書き込む際、MHAIOFile は +1.0 を超える値と -1.0 未満の値をすべてクリッピングします。クリッピングを避けるには浮動小数点 WAVE ファイルを使用してください。

**MHAIOFile の変数:**

| 変数 | 説明 |
|---|---|
| `in` | 入力ファイル名。 |
| `out` | 出力ファイル名。 |
| `output_sample_format` | 出力サンプル形式。入力ファイルから形式仕様をコピーする場合は `input`。 |
| `startsample` | 処理する最初のサンプル。 |
| `length` | 1回の start コマンドで処理するサンプル数。すべて処理する場合は 0。 |
| `strict_channel_match` | MHA と入力サウンドファイルで同じチャンネル数を要求します。yes の場合、チャンネル数が一致しないとエラーメッセージが生成されます。そうでなければ、追加のチャンネルは無視され、不足しているチャンネルはゼロで埋められます。 |
| `strict_srate_match` | MHA とサウンドファイルで同じサンプリングレートを要求します。yes の場合、サンプリングレートが一致しないとエラーが報告されます。そうでなければ、サウンドファイルのサンプリングレートは無視されます（リサンプリングなし）。 |
