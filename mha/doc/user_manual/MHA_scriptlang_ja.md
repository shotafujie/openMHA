# openMHA 設定言語

> この文書は [MHA_scriptlang.tex](MHA_scriptlang.tex) の日本語訳です。

## 概要

openMHA フレームワークとほとんどの openMHA プラグインは、openMHA 設定言語を通じて制御されます。この言語は openMHA ライブラリに実装されています。階層的な設定が可能です。各設定レベル（パーサー）は変数やサブパーサーなどのアイテムを含むことができます。任意のアイテムのプロパティを照会できます。アイテムへの書き込みアクセスは C++ コールバック関数に接続できるため、オーディオ信号の処理中に openMHA とすべてのプラグインの設定と状態を変更することが可能です。

openMHA 設定言語は、行ベースの人間が読めるテキストコマンドで構成されています。openMHA 設定言語インタープリターは、テキストファイルの読み込みまたは TCP ネットワークストリームを通じてコマンドを受信します。openMHA はテキストインターフェースを使用する C++ オブジェクトを介して設定言語パーサーへのアクセスも提供しており、openMHA を他のアプリケーション（例: Octave や Matlab からのアクセス）に組み込むことができます。

## openMHA 設定言語の構造

openMHA 設定言語コマンドはシンプルな構造を持っています: 各コマンドは左辺値、演算子、右辺値で構成されます。3つの演算子が定義されています:

- **アクセス演算子 "="** — 変数の値を設定するために使用します。
- **クエリ演算子 "?"** — 変数やその他のノードの値、型、その他の情報を照会するために使用します（いくつかの例外あり）。
- **下降演算子 "."** — 階層的な openMHA 設定の次のレベルに降下します。

各左辺値はパーサーエントリの名前です。すべての演算子がすべてのパーサーエントリで利用可能なわけではありません: サブパーサーは "?" と "." のみをサポートし、モニターは "?" のみをサポートします。設定ファイルでは、openMHA スクリプト言語コマンドを複数行に分割できます: 行が "`...`" で終わる場合、次の行が追加されます。これはコマンドプロンプト（TCP インターフェースなど）では適用されません。

openMHA 設定言語は強い静的型付けを備えており、変数のデータ型はその変数を実装するプラグインによって定義されます。書き込みアクセス（"="）など多くの設定言語コマンドは、プラグイン開発者によって C++ コールバックに接続できます。

### クエリコマンド

右辺値なしのクエリ演算子は、パーサーアイテムの内容を人間が読める形式で表示します。クエリ演算子に右辺値を渡すことで、クエリの種類を変更できます。クエリ演算子とその右辺値の組み合わせを **クエリコマンド** と呼びます。有効なクエリコマンドは以下の通りです:

| コマンド | 説明 |
|---|---|
| `?` | パーサー要素の内容を表示します。 |
| `?cmds` | この要素のすべてのクエリコマンドのリストを表示します。 |
| `?help` | 要素の詳細な説明を表示します。 |
| `?val` | 要素の値を返します。 |
| `?type` | 要素のデータ型を返します。 |
| `?perm` | 要素のアクセス権を返します。 |
| `?range` | この変数の有効な値の範囲を返します。 |
| `?subst` | このノードに適用されたすべての変数置換を表示します。 |
| `?entries` | このノードのすべてのエントリのリストを表示します。 |

特殊なクエリコマンド:

| コマンド | 説明 |
|---|---|
| `?save:<filename>` | このノードの内容を要素説明コメント付きでテキストファイル "filename" に保存します。 |
| `?saveshort:<filename>` | このノードの内容を追加のコメントや空行なしでテキストファイル "filename" に保存します。 |
| `?savemons:<filename>` | すべてのモニター変数の内容をファイル "filename" に保存します。 |
| `?read:<filename>` | ファイル "filename" を現在のパーサーノードに読み込みます。 |

### 多次元変数

openMHA 設定言語は、Octave/Matlab の記法と同様の方法でベクトルと行列をサポートしています: ベクトルは角括弧で囲み、アイテムは空白で区切ります。行列はベクトルのベクトルとして記述し、各ベクトルはセミコロンで区切ります:

```
vector = [1.0 2.7 4]
matrix = [[1 2 3];[4 5 6]]
```

実数値のベクトルは `min:increment:max` という特殊な記法もサポートしています。明示的記法とインクリメンタル記法の混合が許可されています。ベクトルは内部的に展開され、読み取り時には明示的な記法を返します:

```
vector = [1.0 1.7 2.1:1.1:5]
```

これは以下のように展開されます:

```
vector = [1.0 1.7 2.1 3.2 4.3]
```

### 複素数変数

複素数値を持つ変数は、実部と虚部の和として括弧内に記述されます。純粋な実数値は括弧なしで記述できます:

```
complex = (1.3 + 2.7i)
vcomplex = [(1.3 + 2.7i) (2.0 - 1.1i) 6.3]
```

### テキスト変数

openMHA 設定言語の文字列は任意の文字を含むことができます。特殊文字を引用符で囲む必要はありません。引用符はリテラルとして扱われます。文字列の先頭と末尾の空白は自動的に削除されます。文字列ベクトルのベクトル要素は単一のスペース文字で区切られます。これは、ベクトル要素にスペースを含めることができないことを意味します。

```
string =  This is a valid text string.
samestr=This is a valid text string.
strvec = [pears bananas green_apples]
```

### 変数の範囲

数値変数は制限された範囲を持つことができ、キーワードリスト変数の値は常にキーワードのいずれかに制限されます。openMHA 設定言語インターフェースを通じて変数が変更される際、新しい値はこの範囲に対してチェックされます。数値変数の場合、範囲は `[x_min, x_max]`（境界値を含む）、`]x_min, x_max[`（境界値を含まない）、またはその混合バージョンが可能です。`x_min` または `x_max` が省略された場合、変数には下限または上限の境界がありません。

キーワードリスト変数の場合、範囲は有効なエントリのスペース区切りリストです。

### 物理単位

距離や時間など物理的な事実を記述する数値変数は、何らかの物理単位で与える必要があります。openMHA でのデフォルトの物理単位は SI 単位です。例えば、時間値には秒、長さにはメートル、質量にはキログラム、力にはニュートン、圧力にはパスカル、面積には平方メートル、速度にはメートル毎秒、周波数にはヘルツです。設定変数がこの規約と異なる場合、変数の説明に使用する単位が記載されます。

設定変数を割り当てまたは読み取る際には、数値のみを指定し、物理単位の名前は数値に付加しません。

### 変数置換と環境変数

openMHA 設定ツリーの各ノードは、テキスト置換のセットを定義できます。置換されるパターンは "`$[VARNAME]`" の形式で、VARNAME は任意のテキストです。このパターンの出現箇所はすべて置換されます。置換のセットは `?subst` クエリコマンドで照会できます。置換は `?addsubst` クエリコマンドで `?addsubst:<VARNAME> <REPLACEMENT>` のスタイルで有効化できます。各パーサーノードは独自のテキスト置換セットを持ち、子パーサーノードには継承されません。

環境変数は openMHA 設定言語で `${VARNAME}` の形式で使用できます。VARNAME は環境変数の名前です。`${VARNAME}` の出現箇所はすべて、openMHA 設定言語の解釈前にその内容で置換されます。つまり、左辺値や演算子さえも置換の一部となることができます。

## openMHA プラグイン間の通信

openMHA の信号処理プラグインは、MHA チェーンプラグイン `mhachain` が提供するような信号処理チェーンでオーディオ信号を処理することが多いです。

これらのプラグインは、あるプラグインの出力信号がチェーン内の次のプラグインの入力信号として処理されるように既に通信しています。オーディオ信号は時間領域の波形データまたはスペクトル領域の短時間フーリエ変換データのいずれかです。

一部のアルゴリズムは複数のプラグインの組み合わせとして実装できますが、現在のオーディオ信号だけでなく、より多くのデータをプラグイン間で共有する必要があります。

openMHA は、**アルゴリズム通信変数**（**AC 変数**）の形でプラグイン間で任意の種類の追加データを共有するメカニズムを提供することでこれをサポートしています。

openMHA に含まれる一部のプラグインは AC 変数を作成し、他のプラグインは他のプラグインが作成した AC 変数を使用するように設定できます。例えば:

- `rmslevel` プラグインは測定されたサウンドレベルを AC 変数として公開します
- `noise_psd_estimator` プラグインはノイズパワースペクトル密度を推定し、AC 変数として公開します
- `smooth_cepstrum` プラグインは別のプラグインが提供する AC 変数からのノイズパワースペクトル密度を使用して信号のノイズを低減します
- `acmon` と `acsave` プラグインは、AC 変数をパーサーモニターにミラーリングしたり、ディスク上のファイルに保存したりすることで、openMHA から AC 変数をエクスポートするために使用できます

AC 変数は名前で識別されます。

AC 変数の命名規約は: `creator_varname`  
ここで *creator* はこの AC 変数を作成するプラグインの設定名（configured name）であり、*varname* は変数の内容または目的を記述します。単一の AC 変数のみを作成するプラグインは、その設定名のみで変数に名前を付けることもあります。

上記のルールはプラグイン開発者への規約であり、openMHA によって強制されるものではないため、この規約に従わないプラグインが存在する場合があります。

コマンドラインツール `analysemhaplugin` を使用して、プラグインが作成する AC 変数の名前を見つけることができます。
