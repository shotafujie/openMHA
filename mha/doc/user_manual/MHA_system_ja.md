# リアルタイム環境のチューニングに関するヒントとリンク

> この文書は [MHA_system.tex](MHA_system.tex) の日本語訳です。

## 概要

低遅延リアルタイム信号処理は、オペレーティングシステムのパフォーマンスに大きく依存するタスクです。合計遅延 4-6 ms の低遅延オーディオ処理には、最大システムレイテンシーを 1 ms または 2 ms 程度に抑える必要があります。シングルプロセッサの高水準オペレーティングシステム（Linux、Windows など）では、マルチタスクは通常、各タスクを限られた時間だけ順次処理し、次のタスクに切り替えることで実現されます。この方法はリアルタイム信号処理には明らかに適していません。コードの実行が予測不可能な時間だけ遅延される可能性があるためです。

低遅延リアルタイム処理タスクは、そのコードの実行を保証する特別なモードで起動する必要があります。さらに、低レベルのシステムタスク（ハードディスクやグラフィックカードへのアクセスなど）による最大中断時間を削減するか、その優先度をリアルタイムプロセスの優先度以下に下げるようにシステムを操作する必要があります。Linux オペレーティングシステムには、これらの機能を提供する修正カーネルが利用可能です。

## Linux オーディオディストリビューション

Linux カーネルを手動でパッチし、最適なオーディオ処理のためにオペレーティングシステムを設定することは、長く困難なタスクです。代わりに、オーディオ処理用に準備・最適化された Linux ディストリビューションの使用を推奨します。少なくとも2つのオーディオディストリビューションが無料で利用でき、そのうちの1つは HörTech が低遅延オーディオ処理に使用しています。

### Ubuntu Studio

広く使用されているオーディオディストリビューションは **Ubuntu Studio** で、Ubuntu ディストリビューションのバリエーションです。低遅延カーネルと openMHA の実行に必要なすべてのソフトウェアパッケージを提供しています。Ubuntu の公式「フレーバー」であるため、Ubuntu 向けのすべてのソフトウェアパッケージが利用可能です。ディストリビューションの新バージョンは年2回リリースされ、長期サポートバージョンは2年ごとにリリースされます。HörTech はこのディストリビューションを使用しており、通常は最新の長期サポートバージョンを使用しています。

詳細とダウンロード: http://ubuntustudio.org/

### Planet CCRMA

もう1つの一般的に使用されるオーディオディストリビューションは **Planet CCRMA** で、Fedora Linux ディストリビューションの上に構築されています。メンテナンスが容易で、MHA での低遅延信号処理に必要なすべてのソフトウェアパッケージ（主に JACK サウンドサーバー、ALSA サウンドカードドライバ、低遅延カーネル）を含んでいます。セキュリティ修正を含むシステムアップデートが利用可能です。

詳細とダウンロード: http://ccrma.stanford.edu/planetccrma/software/

### ALSA

ALSA（Advanced Linux Sound Architecture）サウンドドライバとサポートされるオーディオデバイスに関する情報:

http://www.alsa-project.org/

## JACK 低遅延サウンドサーバー

> 「JACK は、GNU/Linux や Apple の OS X のような POSIX 準拠のオペレーティングシステム用に書かれた低遅延オーディオサーバーです。多数の異なるアプリケーションをオーディオデバイスに接続し、アプリケーション間でオーディオを共有できます。クライアントは独自のプロセスで（通常のアプリケーションとして）実行するか、JACK サーバー内で（プラグインとして）実行できます。」

> 「JACK はプロフェッショナルなオーディオ作業のためにゼロから設計されており、2つの重要な領域に焦点を当てています: すべてのクライアントの同期実行と低遅延動作。」（JACK ウェブサイトからの引用）

openMHA フレームワークはオーディオ入出力に JACK 低遅延サウンドサーバーを使用できます。サウンドドライバレイヤー IO を直接使用するのと比較して JACK を使用する利点は、多くの（ほぼすべての）オーディオクライアントに接続できることです。同時に、ドライバレイヤー（主に ALSA だが他のドライバもサポート）の低遅延機能をクライアントに渡します。

JACK は Linux と Mac OS X で利用可能です。ドキュメントとダウンロードサイト:

http://www.jackaudio.org/

JACK クライアントは実行中のサウンドサーバーに追加できます。クライアントがアクティブな間、API 関数、コマンドラインツール、またはグラフィカルユーザーインターフェースを通じて他のクライアントやハードウェアポートに接続できます。クライアントポートへの/からの複数の接続が可能です。ミキシングツール、グラフィカル制御インターフェース、信号分析ツールなど、多くの便利なツールへのリンクが JACK ウェブサイトにあります。

### JACK の起動

JACK サウンドサーバーは MHA の前に起動する必要があります。一度起動すると、JACK の設定（フラグメントサイズ、サンプリングレート）は固定されます。これらのパラメータを変更するには、すべての JACK クライアントを閉じてサーバーを再起動してください。JACK の起動の詳細は `jackd` のマニュアルページとパッケージドキュメントに記載されています。ここでは MHA 固有の項目のみ説明します。

JACK がネイティブパラメータでハードウェアに直接アクセスする場合に最高のパフォーマンスが得られます。通常これは ALSA の `hw` デバイスで提供されます。デバイス名にデバイス番号とサブデバイス番号を追加する必要がある場合があります。例えば、2番目のサウンドカードとして設定された RME Digi 96 の場合、8チャンネル ADAT モードにアドレスするために `hw:1,1` を使用します。ハードウェアデバイス `hw` を使用する場合、ネイティブパラメータのみがサポートされます。つまり、フラグメントサイズ（JACK: `--period`, `-p`）、ハードウェアバッファ数（JACK: `--nperiods`, `-n`）、サンプリングレート（JACK: `--rate`, `-r`）の制限されたセットのみ設定可能です。

非ネイティブサンプリングレートの使用が必要な場合、問題が発生することがあります。バッファサイズの制限（JACK は2の累乗のみ許可、ALSA はネイティブとユーザーのサンプリングレートの比がハードウェアとユーザーのピリオドサイズの比と同じであることを要求）により、ALSA プラグインドライバでは2の累乗のダウンサンプリングのみがサポートされます。したがって、16 kHz のサンプリングレートは、32 kHz または 64 kHz のサンプリングレートをサポートするサウンドカードを使用する場合にのみ達成できます。正しく動作するために、`~/.asoundrc` ファイルに以下のエントリが必要な場合があります:

```
pcm.mhadev {
    type plug
    slave {
        pcm "hw:1,1"
        rate 32000
    }
}
```

`hw:1,1` をお使いのサウンドカードの正しいデバイス名に置き換えてください。JACK デーモンは `mhadev` サウンドデバイスを使用して起動できます:

```
jackd -d alsa -d mhadev -r 16000 -p 128 -n 2
```

これはサウンドカード `hw:1,1` をネイティブサンプリングレート 32 kHz、ハードウェアバッファ長 256 サンプル、2つのハードウェアバッファで使用します。ハードウェアデバイス `hw` を使用しない場合、ALSA ソフトウェア "plug" レイヤーの使用に関する警告メッセージが表示されます。

上記すべてが機能しない場合でも、JACK の OSS ドライバインターフェースをサウンドカードアクセスに使用することは可能です。OSS では非ネイティブサンプリングレートをより簡単に設定できますが、より長い遅延で動作する可能性があり、オーディオハードウェアパラメータの直接制御ができないという欠点があります。

ALSA 用の JACK プラグインがインストールされている場合（例: Planet CCRMA ディストリビューションに含まれている）、MHA JACK クライアントに自動的に接続する仮想 ALSA デバイスを定義すると便利な場合があります:

```
pcm.mha {
    type plug
    slave {
        pcm {
            type jack
            playback_ports {
                0 MHA:in_1
                1 MHA:in_2
            }
            capture_ports {
                0 MHA:out_1
                1 MHA:out_2
            }
        }
    }
}
```

JACK と MHA が実行中の場合、以下のコマンドでサウンドファイルを MHA を通じて再生できます:

```
aplay -D plug:mha soundfile.wav
```
